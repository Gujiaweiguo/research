## 四维框架（Jason 定，2026-11-20 明确日报、周报共用口径）

四栏固定，按 1–4 排列，不把客户和竞对合为一个商地专项，也不把平台公告、客户需求与机会推断混为一谈。

### 1. AI 行业动态｜找锤子：有哪些可迁移的企业 AI 能力？
独立检索中国及海外，不限商业地产；看零售、金融、制造、物流等行业的企业应用、可复用的能力、产品和工作流。每条回答「这把锤子能做什么、已经解决过哪类问题、用了什么条件」。优先有企业名称、场景、部署阶段及效果的案例；平台新能力如确有应用意义可单列为供给侧线索，注明成熟度，不能当客户落地。单纯模型跑分、编程工具版本与融资不是本栏主线。不要求每把锤子当天就找到商地钉子。

### 2. 商业地产客户需求｜找钉子：客户真正想解决什么？
看中美商业地产业主、商管/运营方的具体岗位、任务、现行流程和痛点。优先从客户公开表达、采购招标、试点、上线与使用反馈找证据；应用案例是发现需求的线索，不等于行业普遍需求。注明使用方/买方（若已知）、痛点、需求证据和阶段；推断标为「待验证」，不把厂商声称的需求当客户已确认的需求。

### 3. 竞对 AI 应用｜别人做了什么？
参考 `competitors.md`，关注争夺同一笔客户预算的商管系统、会员营销、数字员工及垂直供应商。记录具体 AI 应用/功能、用户和流程、发布/试点/上线状态、已披露客户和交付证据。应用案例可以同时提供需求与竞对证据，但两个维度分别写使用方问题、供应方做法，不复制同一段。无证据标未披露；新增竞对或条目变更须注明理由和出处。

### 4. OPC 机会｜Jason 一个人能切进去的商业地产企业应用是什么？
从前三栏找交集：有可复用能力、有真实客户痛点、竞对覆盖后仍有可切入空间。围绕商管系统、会员系统、数字员工，从明确工作流的一小段做起；不是做一套大而全的替代系统。筛选时写清目标买方/岗位、为什么可能愿意付费、数据权限和集成门槛、单人能否做出/交付/维护、如何低成本验收；给出一个最小验证动作和指标。优先用小范围、低集成或只读方案验证。需要长销售周期、重驻场或高定制的，明确不适合当前 OPC 阶段或暂缓。结合主报告五道采纳门，适用时用字段引擎/解释引擎分析。事实和假设分开，无新证据不硬给机会。

### 日报：收集能改变判断的证据
- 开头一句「今天最值得留意什么」；常规只留 3–6 条高价值信号，不设最低条数，全部无实质新增就直说。四栏都保留，不列长篇搜索流水账。优先近 24 小时；跨行业栏必要时可补近 7 天内未收录的一手证据，保留原始日期并标为补录。
- 每条写「新事实 → 改变了什么判断或留下什么问题 → 源链接和日期」；重要数字注明披露方。找锤子栏允许暂未匹配商地需求，但必须写出可复用的能力和已知使用条件。需求栏注明地域、买方/岗位、现行做法和需求证据；竞对栏写它与既有流程的具体差异，不能把发布等同于交付。
- 机会栏最多 1 个新判断：沿用「客户类型｜岗位｜流程」作为跟踪名称，标注支持或削弱哪条假设、还缺什么关键证据，有反证也收录。未出现新证据就不新造机会。

### 周报：决定下周验证什么、暂不做什么
- 开头给结论：相比上周，哪条判断变了、证据是什么、下一步做什么。四栏照常保留，日报去重后独立补检，优先补最影响决策的缺口或反证，不拼接日报，不每周重建候选清单。
- 在第四栏沿用上周跟踪名称，只维护最相关的 3–5 个候选（不足不补）。标「优先验证 / 继续观察 / 暂不做」，只写本周变化及理由，并指回前面证据或往期所在。分开标「付费意愿未证实 / 买方确认预算或明确采购动作 / 已付费」；访谈的兴趣、免费试用、市场规模都不是付费证据。中美证据分开，不能拿海外案例当国内需求已验证。
- 每周最多选 **1 个「优先验证」动作**，没有够强的信号就写「本周不推进开发」或只补一条关键证据。给出目标买方、现有替代方案（含人工/Excel/原系统）、为什么可能胜出、需要的数据和权限、单人能投入的时间和交付上限、与现行流程比较的指标、继续/停止的条件。没有买方确认或拿不到真实样本时，先找人、找数据或试报价，不先造产品；技术小试通过不等于付费意愿已验证。
